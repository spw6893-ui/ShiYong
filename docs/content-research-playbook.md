# 拾用内容调研与更新规则

本文定义首版内容和后续 Agent 自动更新时“需要调研什么、如何判断是否发布”。网站不追求工具数量，优先保证任务价值、来源和可复核性。

## 1. 每条工具内容必须调研

1. **核心任务**：它最适合完成什么，不能只复制产品宣传语。
2. **目标用户**：普通用户能否在 10 分钟内开始使用。
3. **官方入口**：官网、官方帮助中心或官方开源仓库。
4. **免费范围**：是否有免费计划、额度是否刷新、导出是否带水印。
5. **输入与输出**：支持哪些文件、能生成什么、能否导出和继续编辑。
6. **数据处理**：是否云端上传、是否支持本地处理、训练和保留设置。
7. **限制**：额度、平台、语言、硬件、导出和协作限制。
8. **人工检查点**：事实、引用、数字、素材授权和权限。
9. **替代方案**：什么情况下通用助手已经够用，什么情况下应选择专门工具。
10. **验证日期**：每次核查后更新 `verifiedAt`、`updatedAt` 和 `sources`。

## 2. 来源优先级

按以下顺序取证：

1. 官方帮助中心、产品文档、价格页和隐私说明。
2. 官方产品页、公告和更新日志。
3. 官方 GitHub 仓库、Release 和许可证。
4. 可以重复的实际操作结果。
5. 可信的一方评测，仅用于补充体验，不用于代替官方规则。

导航站、SEO 汇总、营销软文和未经确认的社交媒体内容不能作为价格、隐私和功能事实的唯一来源。

## 3. 方法与工作流必须验证

- 是否从一个真实任务开始，而不是介绍概念。
- 是否提供准备材料、步骤、提示模板和最终检查。
- 是否明确 AI 不应自行补充的信息。
- 是否有隐私、授权或事实核查提醒。
- 普通用户是否能在 10 分钟内开始第一步。
- 工具替换后，方法是否仍然有效。

## 4. 收录评分

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 任务价值 | 30 | 是否解决高频、明确的问题 |
| 上手难度 | 20 | 普通用户能否快速开始 |
| 输出质量 | 20 | 输出是否稳定且容易检查 |
| 成本透明 | 10 | 免费与付费边界是否清楚 |
| 数据安全 | 10 | 是否能说明数据和权限边界 |
| 稳定性 | 10 | 官方入口和维护状态是否可靠 |

- 85—100：可以进入首页精选。
- 70—84：只在明确场景中推荐。
- 60—69：保留为草稿或观察项。
- 低于 60：不收录。

## 5. Agent 自动更新流程

```text
发现候选或变化
→ 读取官方来源
→ 与现有 Frontmatter 和正文比对
→ 只修改发生变化的内容
→ 更新 sources / updatedAt / updatedBy / verifiedAt
→ 保持 status: draft
→ npm run build
→ 创建 Pull Request 和变更摘要
→ 人工确认后改为 published 并合并
```

Agent 不应自动发布以下变化：

- 价格、隐私政策和数据训练规则发生变化。
- 官方入口迁移、产品停止服务或所有权变化。
- 需要注册、支付或上传真实文件才能验证。
- 来源互相冲突，或者只有二手信息。
- 内容涉及医疗、法律、财务或其他高风险建议。

## 6. 每周维护节奏

- 每周：检查失效链接、更新一篇每周总结、处理候选草稿。
- 每月：复核首页工具和高访问内容。
- 每 90 天：工具必须重新核查；过期内容自动显示“待复核”。
- 每季度：删除低价值、重复或长期无人使用的内容，不为了数量保留。

## 7. 首版内容构成

首版保持约 24 条内容：

- 6 条可迁移的 AI 方法。
- 6 条办公与信息处理工作流。
- 3 条学习和研究工作流。
- 8 条经过官方来源核查的工具说明。
- 1 条按任务选择工具的汇总。

后续优先补齐演示制作、表格处理、内容改写和结构图比较，不先扩展到编程、营销、投资或低价账号类内容。
